# المتطلبات الفنية — نظام SMS-Smarthoob (هدهد الفواتير)

> **الحالة:** وثيقة معتمدة ومطابقة للمنظومة الحالية  
> **المرجع:** [خطة مشروع SMS-Smarthoob](./PROJECT-PLAN.md)  
> **النطاق:** تطبيق جوال وويب (React Native / Expo / TypeScript) يجهّز رسائل الفواتير من ملفات CSV/Excel/PDF ويرسلها إلى منصة بوابات هدهد.

---

## 1. الغرض العام

تمكين المستخدم من تجهيز وإرسال رسائل الفواتير المخصصة لعملائه ومشتركيه بأعلى كفاءة، سواءً عبر استيراد ملفات الفواتير أو الاتصال المباشر بقاعدة بيانات المشتركين في البوابة، مع توفير قدرات تحليل ذكية محلية ومزامنة سحابية مرنة تعمل في وضع عدم الاتصال (Offline-First).

---

## 2. أطراف النظام ونطاق الاستخدام

- **المستخدم الأساسي:** مشغّل النظام، مسؤول التحصيل، أو مدير الحملات التسويقية.
- **مصادر البيانات المدخلة:**
  - ملفات المستندات: CSV، Excel (`.xlsx`, `.xls`)، و PDF.
  - القوالب: 7 قوالب افتراضية جاهزة + قوالب المستخدم المخصصة.
  - إعدادات البوابات: نقاط النهاية (Endpoints) ومفاتيح الترخيص وأسماء المرسلين.
- **المخرجات المعتمدة:**
  - سجلات الحملات والمستلمين المخزنة محلياً في SQLite وسحابياً في Supabase.
  - رسائل مخصصة مرسلة عبر منصة بوابة هدهد (HodHod Platform).

---

## 3. المتطلبات الوظيفية (Functional Requirements)

| المعرّف | المتطلب | آلية التنفيذ في النظام الحالي |
|---|---|---|
| **FR-01** | اختيار ملفات CSV / Excel / PDF من ذاكرة الهاتف أو المتصفح مع معالجة الأخطاء. | منفذ عبر `expo-document-picker` مع معالج بديل للمتصفحات. |
| **FR-02** | عرض عينة من بيانات الملف المستخرج واقتراح الأعمدة الأكثر احتمالاً. | منفذ عبر `documentParser.ts` ومحلل خادم FastAPI. |
| **FR-03** | دعم اختيار القالب المعتمد وربط متغيراته تلقائياً بأعمدة الملف. | منفذ عبر `components/DocumentImportModal.tsx` و `suggestMapping`. |
| **FR-04** | دعم المتغيرات باللغتين العربية والإنجليزية (مثل `{{الاسم}}` و `{{المبلغ}}`). | منفذ في دالة `extractPlaceholders` بنمط RegEx يدعم الحروف العربية `\u0600-\u06FF`. |
| **FR-05** | شاشة مراجعة ومعاينة الرسائل قبل الإرسال الفعلي. | منفذ في خطوة `preview` بـ `campaigns.tsx` مع توليد نصوص الرسائل الفردية. |
| **FR-06** | التحقق من صحة أرقام الهواتف وتطبيعها (تنسيق +966 أو 05 أو الدولي). | منفذ في خوارزميات `PHONE_PATTERNS` داخل `documentParser.ts` و `engine.py`. |
| **FR-07** | تأكيد صريح من المستخدم قبل بدء الإرسال الفعلي مع منع الإرسال المزدوج. | منفذ عبر زر الإرسال التفاعلي وحظر الإجراء أثناء خطوة `sending`. |
| **FR-08** | تسجيل ومتابعة حالة كل رسالة وحملة في قاعدة البيانات المحلية. | منفذ في جدول `campaign_recipients` مع حالات `pending`, `sent`, `failed`. |
| **FR-09** | العمل بدون اتصال بالإنترنت (Offline-First). | منفذ عبر `lib/database.ts` باستخدام محرك `expo-sqlite`. |
| **FR-10** | مزامنة تلقائية ويدوية مع السحابة عند توفر الإنترنت. | منفذ عبر دوال `syncWithSupabase()` وزر المزامنة بشاشة الإعدادات. |
| **FR-11** | توفير قوالب افتراضية للقراءة فقط عند التثبيت لأول مرة. | مدمج 7 قوالب فواتير وترحيب افتراضية في تهيئة SQLite. |
| **FR-12** | إمكانية نسخ وتعديل وحذف القوالب مع الاحتفاظ بالقوالب الافتراضية. | محمي عبر قيد `is_default = 0` لعمليات الحذف في SQLite. |
| **FR-13** | خيار التحكم في حجم الدفعات ومعدل الإرسال (Batching & Rate Limit). | متاح في شاشة الإعدادات عبر نموذج `SendingPreferencesForm`. |
| **FR-14** | إمكانية إدخال عنوان خادم الذكاء الاصطناعي واختبار الاتصال به. | متاح في شاشة الإعدادات عبر حقل `API Base URL` وزر فحص الاتصال. |

## 4. متطلبات الذكاء الاصطناعي والتحليل (Smart AI Features)

| المعرّف | الميزة | الوصف والتنفيذ التقني |
|---|---|---|
| **FR-AI-01** | **الاكتشاف التلقائي للأعمدة** | فحص محتوى كل عمود وتحديد نوعه (`phone`, `name`, `amount`, `date`, `text`) مع إعطاء مؤشر ثقة (`confidence`). |
| **FR-AI-02** | **الربط التلقائي للمتغيرات** | مطابقة ذكية بين وسوم القالب وأعمدة الملف بالاعتماد على التشابه اللغوي وقواعد الحقول المالية والشخصية. |
| **FR-AI-03** | **اقتراح القالب المناسب** | تحليل أعمدة المستند واقتراح أفضل قالب ملائم من القوالب المتاحة استناداً لعدد المتغيرات المطابقة. |
| **FR-AI-04** | **المحلل المحلي البديل (Offline Fallback)** | في حال عدم توفر خادم FastAPI، يقوم التطبيق بتحليل ملفات CSV واقتراح الربط محلياً بالكامل على جهاز المستخدم دون إنترنت. |
| **FR-AI-05** | **كشف الأخطاء والقيم الناقصة** | إبراز الصفوف التي تفتقد لأرقام الهواتف أو القيم الضرورية لمنع إرسال رسائل غير مكتملة. |

## 5. قواعد العمل الأساسية (Business Rules)

1. **الرقم ونص الرسالة إلزاميان**: لا يمكن اعتماد أو إرسال أي صف يخلو من رقم الهاتف أو ينتج عنه نص رسالة فارغ.
2. **الحفاظ على نصوص أرقام الهواتف**: تُخزن أرقام الهواتف كنوع نصي `TEXT` في SQLite لمنع فقدان الأصفار البادئة أو علامة الزائد `+`.
3. **لا استبدال صامت للبيانات**: أي تعويض لقيمة فارغة يجب أن يكون واضحاً للمستخدم في شاشة المعاينة.
4. **حماية المفاتيح السرية (Zero Leakage)**: مفاتيح API الخاصة ببوابات الإرسال تظل مشفرة في السحابة وتُستدعى فقط عبر دوال الخادم `hoodhad-send`.
5. **استمرارية السجلات المحلية**: إغلاق التطبيق أو فقدان الطاقة لا يؤثر على مسودات الحملات أو القوالب؛ كل عملية تُحفظ لحظياً في SQLite.

---

## 6. المتطلبات غير الوظيفية (Non-Functional Requirements)

- **استجابة الواجهة (UI Responsiveness):** جميع عمليات قراءة الملفات والاستعلام عن قاعدة البيانات والمزامنة الشبكية تتم بشكل غير متزامن (Asynchronous) بعيداً عن خيط الواجهة الرئيسي (UI Thread).
- **الأمان والخصوصية (Security & Privacy):** بيانات المستندات وأرقام العملاء تُحلل في الذاكرة ولا تُرفع لأي خوادم خارجية غير مصرح بها.
- **التوافقية (Cross-Platform):** شفرة برمجية موحدة تعمل على أنظمة Android و iOS والويب باستخدام React Native و Expo.
- **دعم اللغة العربية والـ RTL:** تصميم الواجهات موجه بالكامل لليمين مع مراعاة محاذاة الأيقونات وحقول الإدخال والخط العربي الأصيل (Cairo).
