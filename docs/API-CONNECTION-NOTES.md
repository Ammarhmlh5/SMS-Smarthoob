# ملاحظات الاتصال ببوابات الرسائل

## المعمارية الحالية

- التطبيق هو المسؤول عن إعداد الحملات، حفظها محلياً، جلب المستلمين، وإرسال الرسائل.
- تُحمّل إعدادات البوابة وتفضيلاتها من Supabase مباشرة باستخدام جلسة المستخدم وRLS.
- يتصل التطبيق مباشرة بعنوان البوابة المحفوظ. لا يمر الإرسال أو جلب المشتركين عبر Supabase Edge Functions.
- تُحلل ملفات CSV على الجهاز. تستخدم خدمة تحليل المستندات فقط للأنواع التي لا يدعمها المحلل المحلي، ويجب أن تعيد كل الصفوف؛ لا تُستخدم عينات الخادم كقائمة مستلمين.
- إذا كان للمستند عمود رسالة جاهزة، يستخدمه التطبيق مباشرة. وإلا يركب الرسالة محلياً من القالب وبيانات الصف.

## إدارة إعدادات البوابة

يقرأ التطبيق سجلات المستخدم من `gateway_connections` و`gateway_settings` باستخدام Supabase Client. تقيد سياسات RLS الوصول إلى سجلات المستخدم المصادق عليه. تتضمن بيانات الاتصال عنوان HTTPS واسم المرسل ومفتاح API.

لأن الإرسال مباشر، يصل مفتاح API إلى ذاكرة التطبيق ويُرسل إلى البوابة فقط في ترويسة `Authorization`. لا يمكن اعتبار المفتاح سراً عن مالك الجهاز أو عن نسخة تطبيق معدّلة؛ يجب قصر الصلاحية والحصة في إعدادات البوابة، وتدويره عند الاشتباه بكشفه.

## عقد الاتصال بالبوابة

### جلب المستلمين

يطلب التطبيق `GET` إلى عنوان البوابة مع:

```http
Authorization: Bearer <api-key>
Accept: application/json
```

تُقبل قائمة مباشرة أو قائمة ضمن `data` أو `subscribers`. لكل عنصر يلزم حقل هاتف أو بريد إلكتروني، ويمكن توفير الاسم والرسالة الجاهزة.

### إرسال رسالة

يرسل التطبيق `POST` مستقلاً لكل مستلم، مع الترويسات السابقة وإضافة `Content-Type: application/json`، والحمولة:

```json
{
  "sender": "اسم المرسل",
  "to": "+966500000000",
  "message": "نص الرسالة"
}
```

تعني استجابة HTTP من فئة 2xx قبول البوابة للطلب. يعاد فقط على أخطاء الشبكة و`429` و`502` و`503` و`504`، مع احترام `Retry-After` والتأخير التدريجي المحلي. تحفظ حالات الرسائل والتقدم في SQLite على الجهاز.

## قيود المنصات والنشر

- تطبيقات Android وiOS تتصل مباشرة بالبوابة؛ لا حاجة إلى CORS لطلبات تطبيقات الهاتف الأصلية.
- نسخة الويب تحتاج أن تسمح البوابة بطلبات CORS من نطاق التطبيق، وإلا يفشل الاتصال من المتصفح.
- تم إيقاف `hoodhad-send` و`gateway-settings` كمساري إرسال وإدارة خادميين؛ تعيدان `410 Gone` بعد نشر النسخ الحالية. يجب نشر التغيير إذا كانت النسخ القديمة منشورة في Supabase.
- يجب إبقاء مفاتيح Supabase العامة فقط في التطبيق، وعدم تضمين `service_role` أو أسرار الخادم في التطبيق.
