# خطة اختبار تحسين تبويب القوالب

## 1. الهدف والنطاق

تحدد هذه الوثيقة طريقة التحقق من إنشاء القوالب وإدارتها ومعاينتها، إضافة إلى تسليم ربطات PDF المحفوظة لمسار الاستيراد والتحقق من السجلات الناتجة. لا تختبر المطابقة التلقائية للقوالب أو إرسال رسائل.

## 2. بيئة وأوامر الاختبار

الأوامر المعرفة في `package.json`:

| الغرض | الأمر |
|---|---|
| فحص الأنواع | `npm run typecheck` |
| فحص lint | `npm run lint` |
| الاختبارات الآلية الحالية | `npm test` |
| اختبارات API المحلي الحالية للتحقق من عدم الانحدار عند الحاجة | `npm run test:local-api` |
| بناء الويب | `npm run build:web` |

لا يوجد في الإعداد الحالي أمر مستقل لاختبارات واجهة القوالب؛ لذلك تضاف اختبارات المنطق إلى مشغل Node الموجود، وتنفذ اختبارات الواجهة وPDF يدويًا على المنصات إلى أن يعتمد المشروع إطار اختبارات واجهة.

في اختبار الويب، استخدم تبويبًا واحدًا لكل أصل عند فتح قاعدة SQLite. يعتمد Expo SQLite على OPFS access handles؛ فتح عدة صفحات للتطبيق على الأصل نفسه قد يفشل بإنشاء المقبض ويترك عامل قاعدة البيانات بحالة غير صالحة، فلا يُعد ذلك دليلًا على اختلاف مخطط القاعدة.

يجب تسجيل الأمر ونتيجته وأي فشل معروف في تقرير التحقق الخاص بالتنفيذ. لا تُعتبر اختبارات الويب بديلًا عن تجربة عارض PDF الأصلي على جهاز أو development build.

## 3. مستندات الاختبار المسموح بها

يقتصر اختبار إنشاء القوالب يدويًا على ملفات المستندات الموجودة في `مستندات عينات` داخل المشروع:

- `ابريل ط4.xlsx`
- `فواتير عينه.pdf`
- `كشف تحصيل عينه.pdf`
- `كشف تحصيل عينه2.pdf`
- `كشف تسديد عينه.pdf`
- `كشف فصل عينه.pdf`

لا تُنشئ CSV أو PDF تجريبيًا، ولا تستخدم ملفًا خارج هذه المجموعة لاختبار إنشاء القالب. تُبنى نصوص القوالب من عناوين البنود المستخرجة، مع إبقاء قيم الأشخاص والفواتير في معاينة المستند وعدم نسخها إلى نص القالب.

تظل نتائج الاختبارات التاريخية أدناه كما نُفذت؛ أما الاختبارات الجديدة فتلتزم حصريًا بملفات المشروع المذكورة.

## 4. اختبارات المنطق

| المعرّف | المتطلب | الحالة | النتيجة المتوقعة |
|---|---|---|---|
| **TPL-TC-01** | `TPL-FR-03` | استخراج `{{name}}` و`{{اسم_المشترك}}` | استخراج الاسمين بترتيب ظهورهما. |
| **TPL-TC-02** | `TPL-FR-03` | ظهور المتغير نفسه عدة مرات | إرجاع متغير واحد في قائمة المفاتيح، مع بقاء جميع مرات الظهور في النص. |
| **TPL-TC-03** | `TPL-FR-03` | أحرف غير مدعومة أو أقواس غير مكتملة | عدم اعتبار النص غير المطابق متغيرًا صالحًا، وإظهاره للمستخدم إن كان ذلك يسبب التباسًا. |
| **TPL-TC-04** | `TPL-FR-04`, `TPL-FR-07` | متغير في النص بلا ربط | النتيجة غير مكتملة وتذكر اسم المتغير. |
| **TPL-TC-05** | `TPL-FR-05`, `TPL-FR-07` | ربط عمود باسم فارغ أو نوع غير معروف | رفض المصدر برسالة/خطأ محدد، وعدم اعتباره صالحًا. |
| **TPL-TC-06** | `TPL-FR-05` | منطقة PDF صحيحة ضمن النطاق | قبول الإحداثيات عندما تكون منتهية، ضمن 0..1، ولها مساحة موجبة. |
| **TPL-TC-07** | `TPL-FR-05` | منطقة PDF خارج النطاق أو ذات مساحة صفرية/سالبة | رفض المنطقة. |
| **TPL-TC-08** | `TPL-FR-08` | قيم عينة متاحة لكل المتغيرات | عرض معاينة تحوي القيم التجريبية في مواضعها. |
| **TPL-TC-09** | `TPL-FR-08` | قيمة عينة غير متوفرة لمتغير | تمييز المتغير غير المحلول؛ لا تظهر المعاينة كرسالة مكتملة. |
| **TPL-TC-10** | `TPL-FR-02` | اسم أو نص فارغ، أو يتجاوز الحد | رفض الإدخال مع بيان الحقل والحد الحالي. |
| **TPL-TC-11** | ربط PDF بالصفوف | ربط منطقة صفوف مع عمود آلي على مستوى الصفحة | تكرار قيمة العمود الآلي في سجلات الصفحة نفسها، مع بقاء قيم المناطق متطابقة حسب رقم الصفحة والسطر. |
| **TPL-TC-12** | ربط PDF بالصفوف | يشير ربط العمود إلى مصدر غير موجود | إظهار خطأ يحدد العمود؛ عدم إسقاط الربط أو إنشاء سجلات بقيم فارغة بصمت. |
| **TPL-TC-13** | ربط PDF بالصفوف وإعداد المستلمين | تسمية متغير منطقة الصفوف «رقم الهاتف» | اقتراح العمود الناتج للهاتف، واستخدام قيمة كل صف في المستلم المقابل. |
| **TPL-TC-14** | إعداد المستلمين | رقم هاتف فارغ أو غير صالح في أي صف | منع تأكيد الربط مع بيان رقم الصف والطلب باختيار عمود صالح؛ عدم إسقاط المستلم بصمت. |

## 6. اختبارات التخزين والمزامنة

| المعرّف | السيناريو | النتيجة المتوقعة |
|---|---|---|
| **TPL-DATA-01** | إنشاء قالب بربط عمود ثم إعادة تحميله من SQLite | بقاء النص والربط مطابقين لما حفظه المستخدم. |
| **TPL-DATA-02** | حفظ ربط منطقة PDF ثم إعادة تحميله | بقاء نوع المصدر والإحداثيات صحيحة. |

| **TPL-DATA-04** | قراءة قيمة ربط JSON تالفة | رفض البيانات بوضوح أو تسجيل فشل قابل للتتبع؛ لا تُحوّل بصمت إلى نجاح. |
| **TPL-DATA-05** | العمل دون اتصال | بيان حالة الحفظ المحلي والمزامنة المعلقة بوضوح، دون الادعاء أن السحابة حدثت. |
| **TPL-DATA-06** | قالب قديم بلا `variable_mappings` أو بقيمة `{}` | فتحه وتعديله دون فقد الاسم أو نص الرسالة. |
| **TPL-DATA-07** | فشل قراءة SQLite ثم فشل الرجوع للخادم | إظهار فشل تحميل واضح والاحتفاظ بسببي SQLite والخادم للتشخيص. |

تُختبر تحديثات Supabase باستخدام حساب وبيئة تطوير مصرح بها، مع الحفاظ على سياسات RLS وعدم استخدام بيانات إنتاج حقيقية.

## 8. اختبارات حدود النطاق وعدم الانحدار

- فحص تدفق إنشاء القالب للتأكد من أن قراءة مستنده المرجعي لا تستدعي FastAPI ولا ترفع الملف إلى خادم.
- التأكد من أن التغيير لا يضيف مطابقة تلقائية بين قالب ومستند جديد.
- تشغيل `npm test` بعد تعديلات المنطق؛ وتشغيل `npm run test:local-api` عند الحاجة لتأكيد سلامة الاختبارات العامة ذات الصلة.
- يقتصر تعديل `DocumentImportModal` على تطبيق ربطات PDF المحفوظة للقالب المختار؛ لا تغيّر مسارات CSV/Excel أو قواعد الإرسال.
- التحقق من أن معاينة إعداد القالب لا تغيّر سلوك `renderMessage` أو نصوص الرسائل في مسارات أخرى.

## 9. شروط النجاح والإبلاغ

يعد الاختبار ناجحًا عندما:

- تنجح كل حالات P0 المرتبطة بالمتطلب المنفذ.
- لا توجد حالة يظهر فيها متغير ناقص كأنه قيمة صحيحة أو رسالة مكتملة.
- تبقى بيانات القوالب الحالية قابلة للقراءة والتعديل.
- لا يُفقد إدخال المستخدم بصمت عند فشل الملف أو الحفظ.
- لا يظهر طلب شبكة لإرسال مستند إنشاء القالب إلى FastAPI.
- تنجح أوامر lint وtypecheck والاختبارات ذات الصلة.

عند الفشل، يسجل التقرير: معرّف الاختبار، المنصة، خطوات إعادة الإنتاج، النتيجة الفعلية، النتيجة المتوقعة، وهل يمس نطاق القوالب فقط أم يكشف اعتمادًا خارج النطاق.

| ناجح | الويب — عمليات إنشاء وتعديل وحذف القالب بعد إحاطة كل عملية وسجل مزامنتها بمعاملة | على أصل اختبار معزول، نجح الإنشاء وتحديث النص والحذف، عاد عداد القوالب المخصصة إلى صفر، وبقيت القوالب الافتراضية السبعة. ظهرت حالة انتظار المزامنة بسبب `503`، ثم أزيلت قاعدة الاختبار وأوقف خادمها المؤقت. |
| متابعة تشخيصية | أصل الاختبار السابق `localhost:8083` | ظهر SQLite `disk I/O error` عند إعادة التحميل، ثم عرضت قراءة لاحقة القوالب المحلية السبعة دون الخطأ. لم تُجرَ عليه كتابات اختبارية إضافية؛ لا يُمسح الأصل ولا يعاد ضبطه قبل تحديد السبب وأثره على البيانات. |
| ناجح | مزامنة PostgreSQL المحلية — CRUD معزول | أُنشئت قاعدة `sms_smarthoob` على PostgreSQL 18 المنفذ `5433`، وأصبح `/health` يعيد `200 status=ok`. نجحت مصادقة الجلسة المحلية. أُنشئ قالب مؤقت عبر API برمز `201` ثم قُرئ برمز `200` وحُذف برمز `204`، ثم تحققت من حذف الصف دون ترك بيانات اختبار. اجتازت دورة REST والاختبارات المحلية الخمسة وواجهة الويب الناتجة. تبقى اختبار دورة مزامنة سجل SQLite الفعلية وإعادة المحاولة على بيانات المستخدم للتحقق على منصة أوسع. |
| ناجح | مزامنة واجهة القوالب الفعلية إلى PostgreSQL | أُنشئ عبر الواجهة قالب باسم «قالب مزامنة اختباري» من أصل الويب `localhost:8082`. ظهرت محاولة SQLite المحلية الأولية خطأ `Error finalizing statement`، ثم نجح المسار البديل المباشر إلى الخادم، وعرضت الواجهة «تمت مزامنة القوالب مع الخادم». ثُبت ظهور الصف في PostgreSQL بنفس الاسم؛ القالب الاختباري لم يُحذف من بيانات المستخدم. |
| ناجح | اختبار إنشاء قالب كامل بملف CSV | نجح استيراد ملف CSV واستخراج أعمدة الاسم والمبلغ ورقم_الفاتورة وعينات القيم. أُنشئ قالب «قالب اختبار إنشاء كامل» برسالة تحتوي المتغيرات الثلاثة، وأصبحت حالته جاهزة ومزامنًا مع PostgreSQL. ثُبت في PostgreSQL النص والربطات الثلاثة إلى الأعمدة المقابلة. كشف الاختبار تكرار placeholder عند الربط؛ صُحح المنطق ليحدّث الربط دون إدراج placeholder موجود، وأضيف له اختبار آلي. |
| ناجح | اختبار إنشاء قالب عبر المتصفح | أُنشئ قالب «اختبار إنشاء عبر المتصفح» في الواجهة على `localhost:8082` مع استيراد CSV واستخراج الأعمدة الثلاثة وربطها بالنص وإظهار معاينة كاملة. تحققت الواجهة من عدم تكرار placeholders بعد الربط، وعرضت القالب كـ«جاهز» و«تمت مزامنة القوالب مع الخادم». ثُبت صف PostgreSQL ونفس النص وثلاث ربطات الأعمدة. ظهر خطأ SQLite المتقطع `no such table: templates`/`Error finalizing statement` في أصل الويب، وتمت المزامنة عبر المسار البديل المباشر. |
